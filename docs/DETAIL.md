# 每日交接

在侧边栏「每日交接」页面里维护一份交接清单。到点后，每条启用的交接都会新建一个会话、按工作区落位、用「前缀 + 明天的月日」命名，并把交接指令作为第一条消息发出去。

## 定时

页面顶部只有一条全局 cron 表达式，5 段格式（分 时 日 月 周），本地时区：

| 例子 | 含义 |
|---|---|
| `40 15 * * 1-5` | 周一到周五 15:40 |
| `30 9,15 * * 1-5` | 周一到周五 9:30 和 15:30 |
| `0 20 * * *` | 每天 20:00 |

保存后会显示未来三个具体时间。右边的开关停用整条定时，停用期间不触发，重新启用后按当前表达式重新计算。

支持 `*`、`*/n`、`a-b`、`a-b/n`、`a,b`，以及 `jan-mar`、`mon-fri` 这类三段英文缩写。日和周的字段同时写死时，按「任一满足」判定，与经典 cron 一致。

## 不补跑

定时只在命中的那一分钟执行。如果那一刻 DSH 没有运行（关机、退出），这次交接就永久跳过，下次启动不会追溯补做。

## 交接条目

每条交接包含：

- **交接指令** —— 新会话收到的第一条消息，例如 `@docs/HANDOFF.md run the handoff section`。
- **名字前缀** —— 新会话名 = 前缀 + 明天的 `MMDD`。今天 15:40 触发、前缀 `任务`，得到 `任务1124`。
- **工作区** —— 从当前所有工作区中选择，新会话建在该工作区的目录里。选「跟随最近活跃会话」时，取最近活动的那个会话所在的工作区。

每条都有启用/停用开关：行首圆点表示状态，定时只执行已启用的条目，并按列表顺序依次执行。「立即交接」不受启用状态和定时影响，随时可以手动触发。同一条目 5 分钟内重复触发会被忽略，避免误点产生两个会话。

## 存到哪里

状态保存在 `%LOCALAPPDATA%\dsh-session-handoff\state.json`。删掉这个文件就回到初始状态（默认表达式 `40 15 * * 1-5`、空列表）。

## 给 Agent 的工具

插件的 `handoff` 工具可以 `list`、`create`、`update`、`delete`、`toggle`、`run`，改的是同一份数据，和页面完全同步。例如让 Agent 新建一条交接：

> 帮我加一条交接，指令 `@docs/HANDOFF.md run the handoff section`，前缀 `任务`

这个工具使用**延迟加载**（`deferLoading`）：它的参数定义平时不占上下文，只有某一轮真的要用时才读入，因此不会给每个会话增加固定 token 开销。代价是 Agent 第一次使用时可能先查一次它的参数。

工具只是页面的第二个入口。定时、建会话、命名、置顶、发送指令都不经过它，所以工具是否被调用不影响交接本身。
